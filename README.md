# הכסף שלי: הוראות הפעלה

אתר אחד (`index.html`) ששומר את הנתונים ב-Firebase. הנתונים מסונכרנים בין מכשירים, עובדים גם בלי אינטרנט, וכל משתמש רואה רק את החשבון שלו.

## קבצים

| קובץ | תפקיד |
|---|---|
| `index.html` | האפליקציה עצמה (כולל ה-`firebaseConfig`) |
| `sw.js` | פתיחה גם בלי אינטרנט, וגרסה חדשה מופיעה מיד |
| `manifest.webmanifest`, `icon-*.png` | הוספה למסך הבית כאפליקציה |
| `firestore.rules` | כללי האבטחה (העותק כאן לתיעוד, הם נטענים מהקונסול) |

## הגדרה חד-פעמית ב-Firebase

1. **Authentication > Sign-in method:** להפעיל **Email/Password** (זו שיטת הכניסה היחידה באפליקציה).
2. **Authentication > Settings > Authorized domains:** להוסיף `idot10.github.io`.
3. **Firestore Database:** ליצור מסד נתונים במצב Production.
4. **רשימת המאושרים:** ליצור את האוסף `allowlist` (ראו הסעיף הבא) **לפני** פרסום הכללים.
5. **Rules:** להדביק את `firestore.rules` בלשונית Rules וללחוץ Publish.

## מי יכול להשתמש (allowlist)

גישה מקבל רק מי ששני התנאים מתקיימים אצלו: האימייל שלו מאומת, וקיים באוסף `allowlist` מסמך ששמו הוא האימייל שלו באותיות קטנות.

**להוסיף משתמש:** Firestore Database > Data > האוסף `allowlist` > Add document.
- Document ID: האימייל באותיות קטנות (לא Auto-ID), למשל `name@gmail.com`.
- שדה: `approved`, סוג boolean, ערך true.

**להסיר משתמש:** למחוק את המסמך שלו.

מי שלא ברשימה יכול ליצור חשבון, אבל יראה מסך "אין גישה עדיין" ולא יוכל לקרוא או לכתוב נתונים.
הוספה והסרה לא דורשות פרסום מחדש של הכללים.

## התקנה באייפון

פותחים את הכתובת ב-Safari, נכנסים, ובלחצן השיתוף בוחרים **הוסף למסך הבית**.

קישור `?quickadd` לכתובת האתר פותח ישר את חלון ההוספה, מתאים לקיצורי דרך.

## מבנה הנתונים

הכול תחת `users/<uid>/`: `categories`, `tx`, `assets`, `liabilities`, `history`, ו-`meta/profile`.
האוסף `allowlist` הוא ברמה העליונה, ורק אתה עורך אותו.
אוספים ישנים מגרסאות קודמות של האתר (`transactions`, `snapshots`, `meta/settings`) לא בשימוש, ואפשר למחוק אותם ידנית מהקונסול.

## גיבוי

בהגדרות: **ייצוא גיבוי** (קובץ JSON) ו-**ייבוא מקובץ**. הייבוא מעדכן פריטים עם אותו מזהה ולא מוחק את היתר. הוא מקבל גם גיבויים של הארטיפקט המקורי, אם נשמרו כקובץ `.json`.

## פתרון בעיות

- **"הדומיין הזה לא מורשה":** חסר שלב 2 בהגדרה.
- **"אין גישה עדיין":** אין מסמך ב-`allowlist` לאימייל הזה, או שהוא נכתב באותיות גדולות או עם שגיאה, או שהכללים לא פורסמו.
- **נעול בחוץ אחרי פרסום הכללים:** לא נוצר מסמך לאימייל שלך ב-`allowlist` לפני הפרסום. יוצרים אותו עכשיו ומנסים שוב.
- **אחרי עדכון הקוד האפליקציה עדיין נראית ישנה:** נסגור אותה לגמרי ונפתח שוב. אם צריך, מעלים את `CACHE` ב-`sw.js` (`finance-shell-v4` וכן הלאה).
