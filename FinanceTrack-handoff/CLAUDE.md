# הכסף שלי – הנחיות לעבודה על הפרויקט

הקובץ הזה נטען אוטומטית בכל session של Claude Code. הוא מסכם את מה שהוחלט עד גרסה 1.0.2 (אוקטובר 2026).
כשמשהו כאן משתנה (תהליך, מבנה נתונים, מצב נוכחי), מעדכנים את הקובץ באותו PR.

## עם מי עובדים ואיך

- **עידו** הוא הבעלים. מדברים איתו **בעברית**, בהסברים ברורים, ואפשר עם אנלוגיות.
- **לפני כל פיצ'ר או שינוי: קודם מציגים תוכנית ומחכים לאישור.** עידו מבקש את זה במפורש ("אל תשנה כלום, קודם תגיד לי מה אתה חושב").
  התוכנית כוללת: מה ישתנה במסך, האם משתנה מבנה הנתונים, עלות קריאות/כתיבות אם רלוונטי, ושאלות פתוחות.
- מבדילים בין מה שנבדק (בדיקות אוטומטיות) לבין מה שלא נבדק (אייפון אמיתי, Firebase אמיתי). לא מציגים הערכות כעובדות.
- עידו בודק בעצמו על האייפון. בכל PR כותבים **מה לבדוק בטלפון**.

## מה זה

אפליקציית ווב (PWA) לניהול כסף אישי, בעברית ו-RTL, לאייפון:
- **מעקב יומי:** הוצאות והכנסות, קטגוריות עם אימוג'י וצבע, תזרים חודשי, סינונים ופילוחים.
- **שווי נקי:** נכסים והתחייבויות, עדכון לכל פריט או "עדכון מלא", גרף מגמה, היסטוריית עדכונים.
- **חשבונות:** Firebase Auth (אימייל+סיסמה בלבד, עם אימות אימייל) ו-Firestore. כל משתמש רואה רק את הנתונים שלו.
- אירוח: GitHub Pages מהענף `main`, תיקיית השורש. כתובת: https://idot10.github.io/FinanceTrack/

## מבנה הריפו

| נתיב | מה זה |
|---|---|
| `index.html` | **האפליקציה החיה (ייצור).** קובץ אחד: HTML + CSS + JS (vanilla, `<script type="module">`). בלי build. |
| `sw.js` | Service worker: קבצי האתר network-first (גרסה חדשה מופיעה מיד), ספריות Firebase cache-first. שם המטמון לפי סביבה. |
| `manifest.webmanifest`, `icon-*.png` | התקנה למסך הבית |
| `beta/` | **סביבת הבדיקה.** `beta/index.html` ו-`beta/sw.js` הם אותו קוד; ל-`beta/` יש manifest ואייקונים כתומים משלה |
| `firestore.rules` | **תיעוד בלבד.** הכללים האמיתיים נטענים ידנית ב-Firebase Console |
| `tests/` | בדיקות אוטומטיות (jsdom + Firestore מדומה). `npm test` |
| `tests/fixtures/finance-backup-demo.json` | גיבוי לדוגמה: 6 חודשים, 375 תנועות, שווי נקי עם היסטוריה. נוצר ע"י `gen-demo.py` (דטרמיניסטי) |
| `docs/feature-proposals.md` | רשימת הפיצ'רים של עידו עם תעדוף |
| `.nojekyll` | GitHub Pages מגיש את הקבצים כמו שהם, בלי Jekyll |

ה-`firebaseConfig` בתוך `index.html` ציבורי בכוונה (כך Firebase עובד). האבטחה היא בכללים.

## תהליך עבודה (חובה)

1. **כל שינוי בקוד האפליקציה הולך קודם ל-`beta/index.html` בלבד** (ו-`beta/sw.js` אם צריך).
   `index.html` בשורש משתנה **רק** ב-PR של "העברה לייצור", שמעתיק את `beta/index.html` **בדיוק, בלי שינוי**.
   (אותו כלל ל-`sw.js`.) הקוד מזהה את הסביבה לפי הכתובת, לכן הקובץ זהה בשתי התיקיות.
2. **מספרי גרסה:** בראש הסקריפט: `const APP_VERSION='x.y.z',APP_BUILD='bN'`.
   - כל קובץ שנמסר לבדיקה מקבל `APP_BUILD` חדש (b1, b2, ...), כדי שעידו יידע בוודאות מה נטען בטלפון (מוצג בהגדרות ובפס הכתום).
   - גרסה חדשה (`APP_VERSION`) מתחילה מ-`b1`.
3. **ענף + Pull Request. לעולם לא לדחוף ישירות ל-`main`.** כל merge ל-`main` = פריסה ל-GitHub Pages.
   PR שנוגע רק ב-`beta/` בטוח למיזוג; PR של העברה לייצור ממוזג רק אחרי שעידו בדק בבטא.
4. **`npm test` לפני כל PR**, ולהוסיף בדיקות להתנהגות חדשה. `npm run test:prod` מריץ את אותן בדיקות על `index.html` בשורש.
5. תיאור PR בעברית: מה השתנה, מה נבדק אוטומטית, **ומה לבדוק בטלפון**.
6. **שחרור:** כשעידו מאשר, release ב-GitHub עם תג `vX.Y.Z` (הוא מחליט מתי; לא כל העברה לייצור היא release).

### שחזור אם משהו נשבר בייצור
מחזירים לשורש את `index.html` (ו-`sw.js`) מהתג/commit הקודם, ב-PR. הנתונים ב-Firestore לא תלויים בגרסת הקוד.

## סביבות: ייצור ובדיקה

| | ייצור | בדיקה |
|---|---|---|
| כתובת | `/FinanceTrack/` | `/FinanceTrack/beta/` |
| נתונים | `users/<uid>/...` | `users/<uid>/beta/main/...` |
| זיהוי בקוד | `ENV==='prod'` | `ENV==='beta'` (לפי `location.pathname`) |

- **משותף לשתיהן:** ההתחברות, `allowlist`, המכסות, האינדקסים, וב-Safari גם `localStorage` (כולל הגדרת המראה).
- כללי האבטחה לא דורשים שינוי לבטא, כי הנתיב שלה נמצא תחת `users/<uid>`.
- בהגדרות של הבטא בלבד: "העתקת הנתונים האמיתיים לבדיקה" (קורא מהייצור, לא כותב אליו) ו"ניקוי נתוני הבדיקה".
- פיצ'ר שמשנה **כללי אבטחה או הגדרות התחברות** משפיע גם על הייצור. במקרה כזה עוצרים ומתייעצים עם עידו (אולי פרויקט Firebase נפרד).

## מבנה הנתונים (Firestore)

הכול תחת שורש הסביבה (`users/<uid>` או `users/<uid>/beta/main`). רשימת האוספים: `DATA_COLS`.

| אוסף / מסמך | שדות |
|---|---|
| `meta/profile` | `seeded`, `createdAt`. כשאין מסמך (מאושר מהשרת), זורעים קטגוריות ברירת מחדל |
| `categories/{id}` | `name, icon, type('expense'\|'income'), color('#RRGGBB'), ord` |
| `tx/{id}` | `type, amount, categoryId\|null, catName, date('YYYY-MM-DD'), note, createdAt(ms)` |
| `assets/{id}` | `name, category(ASSET_CATS id), value, updatedAt(ms)` |
| `liabilities/{id}` | `name, category(LIAB_CATS id), value, updatedAt(ms)` |
| `history/{String(t)}` | `t(ms), a, l, n, note`. נקודה בגרף; נוספת רק אם הסכומים השתנו |

- `ASSET_CATS`: `gemel, hishtalmut, pension, trading, cash, realestate, other`. `LIAB_CATS`: `mortgage, loan, credit, other`.
- `catName` נשמר בתנועה כדי שמחיקת קטגוריה לא תאבד את השם.
- **אוסף `allowlist` ברמה העליונה:** מסמך לכל אימייל מאושר (מזהה = האימייל באותיות קטנות, שדה `approved:true`). נערך רק מהקונסול, חסום מהאפליקציה.
- **כללי האבטחה:** גישה ל-`users/{uid}/**` רק אם `request.auth.uid==uid`, האימייל מאומת, ו-`exists(allowlist/<email>)`.

## חוקי ברזל טכניים

- **כתיבה של יותר ממסמך אחד: רק דרך `D.runOps(ops)`** (חבילות של 10, עד 4 במקביל).
  סיבה: כל כתיבה מריצה `exists()` אחד בכללים, ו-Firestore מגביל batch ל-20 קריאות כאלה. חבילה גדולה נדחית **כולה** כ-`permission-denied`.
  (זה באג אמיתי שקרה: העתקה וייבוא נכשלו.) בדיקה: `beta-tools.test.js` מוודא שאין batch מעל 10.
- **שינויי נתונים רק בהוספה:** שדות ואוספים חדשים אופציונליים. בלי לשנות שמות ובלי למחוק שדות, כדי שגרסה ישנה (מטמון בטלפון) לא תישבר.
- **כל אוסף חדש** חייב להיכנס ל: `DATA_COLS`, ייצוא, ייבוא (`planImport`), מחיקת כל הנתונים, העתקה/ניקוי בבטא, ובדיקות.
- **מסמכים שנוצרים אוטומטית** (למשל תנועות חוזרות בעתיד) מקבלים **מזהה דטרמיניסטי** (תבנית+חודש), כדי ששני מכשירים לא ייצרו כפילות.
- **אייפון:** `navigator.share` חייב להיקרא **ישירות מתוך הלחיצה**, בלי `await` לפניו. לכן הייצוא בשני שלבים (מכינים ← "שמירת הקובץ").
- **שגיאת `permission-denied`** מציגה את מסך "אין גישה" (`D.fail`). בפעולות גדולות (ייבוא, מחיקה) תופסים את השגיאה ומציגים הודעה, כדי לא לנעול בטעות.
- **טעינת נתונים (חיסכון בקריאות):**
  - תמיד במלואם: קטגוריות, נכסים, התחייבויות, היסטוריה.
  - תנועות: החודש הנוכחי + 10 אחרונות + החודש שמוצג במסך התנועות (`wantedMonths`). חודש אחר נטען כשעוברים אליו ומשתחרר כשחוזרים.
  - פעולות שדורשות את כל התנועות קוראות מהשרת פעם אחת: ייצוא, מחיקת הכול, ייבוא (בדיקת קיים). ספירות בסטטיסטיקות: `getCountFromServer`.
- **ייבוא:** מוסיף רק מה שחסר; כשפריט קיים בשני המקומות, **הקיים מנצח**. "קיים" = אותו מזהה, או אותו תוכן
  (קטגוריה: סוג+שם; תנועה: תאריך+סכום+סוג+הערה, עם ספירת כפילויות; נכס: קטגוריה+שם; נקודה: אותו יום ואותם סכומים).
  חשבון עם קטגוריות ברירת מחדל בלבד מייבא מיד; אחרת מוצג סיכום עם אזהרה ומחכים לאישור.
- **מראה:** `fin-theme` ב-`localStorage` (אוטומטי/בהיר/כהה, לכל מכשיר). מוחל בסקריפט קטן ב-`<head>` לפני הציור.
  כל כלל CSS כהה כתוב פעמיים: תחת `@media (prefers-color-scheme:dark)` עם `:root:not([data-theme="light"])`, ותחת `:root[data-theme="dark"]`.
- **Firebase JS SDK** `10.14.1` נטען דינמית מ-`www.gstatic.com` (`FB_VER`). Firestore עם מטמון מקומי (אופליין).

## בדיקות אוטומטיות

- `npm install` פעם אחת, ואז `npm test` (על `beta/index.html`) או `npm run test:prod` (על `index.html`).
- `tests/lib/harness.js` טוען את הקובץ האמיתי ומחליף **רק** את `D.init()` ב-Firestore מדומה (`tests/lib/fakefs.js`).
  לכן לשמור על התבנית `  async init(){ ... },` ואחריה `  onAuth`, ועל הסימונים `/*FB-START*/` ו-`/*FB-END*/`.
- ה-Firestore המדומה אוכף את מגבלת ה-20 ל-batch, ולא מריץ את כללי האבטחה האמיתיים.
- **מה הבדיקות לא מכסות:** אייפון אמיתי (חלון שיתוף, מקלדת, מטמון ה-service worker, מסך הבית), Firebase אמיתי (כללים, אינדקסים, מכסות).

## הגדרות ידניות ב-Firebase Console (עידו עושה)

- **Authentication:** Email/Password בלבד (Google לא מופעל, ולא צריך כפתור). Authorized domains כולל `idot10.github.io`.
- **Firestore → Rules:** התוכן של `firestore.rules`.
- **Firestore → Data → `allowlist`:** הוספת/הסרת משתמשים. מהטלפון: "Request Desktop Website" ב-Safari, אחרת הקונסול קופץ לתוך מסמך ולא מאפשר Add document.
- **מכסה חינמית (Spark):** 50,000 קריאות, 20,000 כתיבות ו-20,000 מחיקות ביום. חריגה עוצרת את השירות עד האיפוס, בלי חיוב.
